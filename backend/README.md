# Pragmatic-dev — Backend

FastAPI backend for the Pragmatic-dev learning application. Serves two features:

1. **Mental-health tips** — reads tips from Redis (generated by the Celery worker) and exposes a liveness trigger + SSE stream.
2. **Chat** — streams assistant replies token-by-token using a LangGraph workflow with direct `astream` (no Celery).

> See [`../.github/PLAN.md`](../.github/PLAN.md) for the finalized architecture decisions.

---

## Tech Stack

- **Python 3.12**, packaged with **uv**
- **FastAPI** + **uvicorn**
- **Redis** (`redis.asyncio`) for the tips cache and chat message bridging
- **sse-starlette** for Server-Sent Events
- **LangChain (LCEL)** + **LangGraph**, OpenAI **GPT-4** (selectable via a **strategy pattern**)

## API Endpoints

| Method | Path            | Description                                                        |
|--------|-----------------|--------------------------------------------------------------------|
| GET    | `/health`       | Service + Redis health check                                       |
| GET    | `/tip`          | Latest mental-health tip from Redis                                |
| GET    | `/tip/liveness` | Sets Redis trigger `true`; returns `"liveness check successful"`   |
| GET    | `/tip/stream`   | SSE stream of the latest tip (emits on change + keepalive pings)   |
| POST   | `/chat`         | Submit a chat message (`session_id`, `message`)                    |
| GET    | `/chat/stream`  | SSE stream of the assistant reply for a `session_id`               |

> Behind nginx these are reachable under `/api` (e.g. `GET /api/tip`).

### Chat flow (why two endpoints)

SSE (`EventSource`) is GET-only, so submission and streaming are split and bridged via Redis:

1. `POST /chat` stores the message in Redis (`chat:pending:{session_id}`, short TTL).
2. `GET /chat/stream?session_id=...` atomically claims it (`GETDEL`), runs the LangGraph workflow, and streams tokens as SSE `message` events, ending with a `done` event.

## Local Development

Requires [uv](https://docs.astral.sh/uv/) and a running Redis.

```powershell
# From backend/
Copy-Item .env.example .env      # then fill in OPENAI_API_KEY

uv sync                          # create venv + install deps
uv run uvicorn app.main:app --reload --host 0.0.0.0 --port 8000
```

Open the interactive docs at http://localhost:8000/docs

### Quick manual checks

```powershell
# Health
curl http://localhost:8000/health

# Liveness trigger
curl http://localhost:8000/tip/liveness

# Submit a chat message, then stream the reply
curl -X POST http://localhost:8000/chat -H "Content-Type: application/json" `
     -d '{"session_id":"demo","message":"Give me a calming tip"}'
curl -N http://localhost:8000/chat/stream?session_id=demo
```

## Configuration

All configuration is environment-driven — see [`.env.example`](./.env.example). Key variables:

| Variable          | Purpose                                    |
|-------------------|--------------------------------------------|
| `REDIS_HOST/PORT` | Redis connection                           |
| `LLM_PROVIDER`    | Strategy selector (`openai`)               |
| `LLM_MODEL`       | Model name (default `gpt-4o-mini`)          |
| `OPENAI_API_KEY`  | OpenAI credentials (**never commit this**) |
| `TIPS_MAX_ITEMS`  | Max tips retained (worker enforces)        |
| `CORS_ORIGINS`    | Allowed origins (comma-separated or `*`)   |

## Notes

- The backend **reads** tips only; the **Celery worker** (separate service) generates and writes them, enforcing the max-10 FIFO cap.
- Chat responses are **not persisted** yet (planned future enhancement).
- Adding a new LLM provider = implement `LLMStrategy` and register it in `app/llm/factory.py` — no call-site changes.
